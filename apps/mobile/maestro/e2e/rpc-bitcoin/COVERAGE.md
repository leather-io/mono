# rpc-bitcoin coverage

Extension specs covered here: `rpc-sign-psbt`, `rpc-message-signing`, `rpc-open`, `rpc-catalog`, `rpc-get-addresses`, `rpc-send-transfer`, `rpc-add-account`.

Every flow opens the test dApp (`${TEST_APP_URL}`, served with `VITE_TEST_APP_MOBILE_E2E=true`) in the Browser tab, taps a card, answers the approver sheet and asserts that the card's verdict reads `PASS`. Variant and negative cards live in `apps/test-app/src/methods/mobile-e2e-bitcoin.ts` (section "Mobile E2E", labels start with `e2e`). Flows that need keys first tap `e2e prime keys`. That card connects Account 1 and caches the `getAddresses` answer the PSBT and transfer builders read. Each later card then raises a single prompt.

Mobile answers a cancel with `4001 User rejected request` for every method. The extension says `User rejected signing PSBT request` for PSBTs, so the cards assert the code only.
