Biometric unlock — UI mockups

Every user-facing surface from the approved plan (.plans/2026-08-04-001-feat-platform-unlock-plan.md), hand-built from the real design system: @leather.io/tokens colors, type scale, spacing, and the existing Button, Input, SettingsButton/ItemLayout, Card, Sheet, and header primitives. The frames cover both password-backed and biometric-only setups: password-first setup with a secondary biometric alternative, mode-aware Settings, automatic high-intent prompting, explicit low-intent authentication, and guarded recovery. They follow your system theme and use Leather's light and dark palettes.

Popup frames: 390px (tokens sizes.popupWidth) Type: heading.03 / label.02 / body.02 / caption.01 Chrome extension only

Font substitution: Leather ships the licensed faces Marche Super (uppercase headings) and ABC Diatype (labels/body), which can't be embedded here. Headings use Arial Black and text uses Helvetica Neue as stand-ins — expect real builds to look slightly better. The dashed panels are Chrome/OS system UI, drawn schematically: Leather never renders or restyles them.

Flow A

Protect the first software wallet

Shown whenever the profile has no software wallet: first install, after reset, or when a Ledger-only profile adds its first software wallet. It preserves today's Set a password screen as the primary path and adds Use biometrics as a secondary alternative. A definitive Chromium capability failure disables that secondary action with an explanatory tooltip; Firefox keeps the existing password-only screen.

Flow B

Discover and enable biometric unlock

Settings is the permanent management and post-setup discovery path. The row appears whenever a software wallet exists and stays hidden in Ledger-only profiles. Password-backed setups confirm the current Leather password before enrollment or replacement. Biometric-only setups are already On and confirm with the currently configured biometric credential before replacement or setting a password.

Flow C

Main unlock

Opening locked Leather from the toolbar icon or Chrome keyboard shortcut is high-intent: with biometric unlock configured, that opening action starts exactly one ceremony immediately—no intermediate Leather button. Cancellation and failure settle on the configured methods: password-backed setups show the focused password form, biometric retry, and Forgot password?; biometric-only setups show biometric retry and Can't use biometrics? with no password field. Dapp-created request windows, restored pages, and direct URLs are low-intent: they never auto-prompt and show only configured explicit methods.

Flow D

Secret Key reveal

Selecting View Secret Key is the high-intent action: it navigates with a one-shot start intent and the ceremony begins immediately—no second confirmation click. The intent is consumed before the ceremony while preserving the selected wallet's fingerprint. Cancellation, back/forward, restore, or direct URLs settle on the methods configured for the profile and never replay the prompt.

Flow E

Add or restore another wallet

These flows run in the full-page tab using today's two-column layout. For an existing software-wallet state, the final Done or mnemonic-submit click renders confirmation in place and starts the configured biometric ceremony without a redundant click. First-software-wallet create and restore flows instead use Flow A; choosing a password continues to today's password-creation form.
